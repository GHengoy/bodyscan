# BodyScan — 실시간 온디바이스 체형분석 웹사이트 설계

작성일: 2026-10-06

## 1. 목표

모바일 브라우저에서 전면 카메라로 사용자의 전신을 실시간 분석해 **자세(정렬)**와 **체형 비율**을 비유 캐릭터 메시지로 알려주고, 체형에 맞는 **옷 스타일을 추천**하는 재미 위주의 사이트. 광고(배너 + 제휴 상품)로 수익화한다.

핵심 제약: **영상·사진 데이터는 저장되지 않고 기기 밖으로 나가지 않는다.** 이것을 "주장"이 아니라 "구조"로 보장하고, 사용자가 그 사실을 화면에서 체감할 수 있어야 한다.

## 2. 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 분석 범위 | 자세 분석(정면·측면) + 체형 비율 + 스타일 추천 |
| 결과 보존 | 화면에서만 표시. 저장 없음. **Web Share API로 결과 카드 PNG 공유만** 가능 |
| 촬영 방식 | 폰을 세워두고 뒤로 물러서는 방식. 전면 카메라, 자동 카운트다운, 가이드 플로우 |
| 포즈 엔진 | MediaPipe Pose Landmarker (`@mediapipe/tasks-vision`, WASM+GPU), 모델·WASM을 같은 사이트에서 서빙 |
| 스택 | Vite + TypeScript, 프레임워크 없음, 서버 코드 0줄, 정적 배포(Vercel/Netlify 등, HTTPS 필수) |
| 배너 광고 | Google AdSense. **시작 화면·결과 화면에만.** 카메라가 켜진 단계에는 광고 슬롯 없음 |
| 상품 슬롯 | 제휴 링크(쿠팡파트너스 등, JSON으로 관리) 우선 → 비어 있으면 네이티브 광고 유닛으로 폴백 |
| 결과 톤 | 비유 캐릭터("운동선수처럼 완벽합니다", "당신은 거북이시군요") + 작은 수치 병기 |

## 3. 프라이버시 보장 장치

1. **서버 없음.** 영상 프레임을 전송하는 코드 경로가 존재하지 않는다. `fetch`/`XMLHttpRequest`/`WebSocket`/`sendBeacon`은 앱 코드에서 사용하지 않는다(모델·WASM 로딩은 라이브러리 내부 fetch, 측정 시작 전 완료. `products.json` 로딩은 시작 화면에서 완료).
2. **프라이버시 인디케이터** (`ui/privacy.ts`): 카메라가 켜진 동안 상단에 상시 표시. `PerformanceObserver`(`resource` 타입)로 **측정 단계 진입 이후** 메인 문서가 발생시킨 네트워크 요청 수를 세어 "네트워크 전송 0건 · 영상은 이 기기 밖으로 나가지 않습니다"를 표시. 0건이 아니면 빨간색으로 요청 수를 보여준다(개발 중 실수 감지 겸용).
3. **광고 격리.** 광고는 교차 출처 iframe에서 동작하므로 카메라 스트림·캔버스에 접근할 수 없다. 추가로 카메라가 켜진 단계(준비·정면·측면)에는 광고 슬롯을 DOM에 두지 않고, 광고 스크립트도 시작/결과 화면에서만 로드한다. iframe 내부 요청은 메인 문서의 Performance 타임라인에 잡히지 않으므로 인디케이터와 충돌하지 않는다.
4. **오프라인 동작.** PWA 서비스워커로 모델·WASM·앱 자산을 캐시. 안내 문구: "모델이 준비되면 비행기 모드로 켜도 동작합니다."
5. **스켈레톤 전용 보기 토글.** 분석 중 캔버스에 영상 대신 선·점만 그리는 모드. "이미지가 아닌 좌표만 다룬다"는 인식 강화.
6. **종료 처리.** 측면 측정 완료 즉시 `MediaStreamTrack.stop()`, `<video>.srcObject = null`, 랜드마크 버퍼 비움. `pagehide`/`visibilitychange(hidden)`에서도 동일 처리. 결과는 메모리에만 존재, `localStorage`/`sessionStorage`/IndexedDB 미사용.
7. **공유 카드.** 결과 카드 PNG는 수치·도식·문구만 담은 캔버스 렌더. 비디오 프레임 픽셀은 절대 그리지 않는다(`drawImage(video, …)` 호출을 shareCard 모듈에서 금지).
8. **데스크톱 접속** 시 "모바일에서 열어주세요" + 현재 URL QR 코드(클라이언트 사이드 생성).

## 4. 화면 흐름 (상태 머신)

```
start → setup → front → side → result
                 ↑ (실패 시 힌트 후 재시도)        → (다시 측정) → setup
```

### 4.1 시작 화면 `start`
- 한 줄 설명, 프라이버시 선언, "측정 시작" 버튼
- 측정 안내: 폰을 허리~가슴 높이에 세워두기, 2~2.5m 뒤로, 밝은 곳, 몸에 붙는 옷
- 하단 AdSense 배너 슬롯
- `products.json`을 이 화면에서 미리 로드(결과 화면에서 네트워크 요청이 생기지 않도록)

### 4.2 카메라 준비 `setup`
- 전면 카메라 권한 요청(`facingMode: 'user'`, 이상적 720p). 미러링 표시.
- 모델 로딩 중 "분석 엔진 준비 중…". 로딩 완료 후 프라이버시 인디케이터 카운팅 시작.
- 전신 가이드 실루엣 표시. **게이트 조건(gating.fullBody)**: 코, 양 어깨, 양 고관절, 양 발목 visibility ≥ 0.6 이고 모두 프레임 안(0.02~0.98). 조건 충족 시 실루엣 녹색 + "좋아요, 그대로 서 계세요".
- 조건이 **1.5초 연속 유지**되면 `front`로 전환.
- 30초 동안 미충족 시 힌트: "더 뒤로 물러나거나 밝은 곳에서 시도해 주세요".

### 4.3 정면 측정 `front`
- 추가 게이트(gating.facingFront): 어깨 너비(x 거리) / 몸통 길이(어깨중점~고관절중점) ≥ 0.45. 미충족 시 "정면을 바라봐 주세요".
- 카운트다운 3-2-1(화면 + 음성 옵션) → **3초간 프레임별 랜드마크 수집 → 좌표별 중앙값**으로 확정(sampler).
- 수집 중 전신 게이트가 깨지면 수집 초기화 후 재시작.

### 4.4 측면 측정 `side`
- 안내 "왼쪽으로 90° 돌아서 옆모습을 보여주세요".
- 게이트(gating.facingSide): 어깨 너비 / 몸통 길이 ≤ 0.2 이고, 한쪽(카메라 쪽) 귀·어깨·고관절·무릎·발목 visibility ≥ 0.6. 왼쪽으로 돌면 카메라에는 **오른쪽 몸**이 보이므로(미러링 고려) 가시성 높은 쪽을 자동 선택하여 그 쪽 랜드마크를 사용.
- 1.5초 유지 → 3초 수집 → 중앙값 확정.
- 완료 즉시 카메라 종료(3-6).

### 4.5 결과 화면 `result`
- 상단 배너: "카메라가 꺼졌습니다. 영상은 어디에도 남지 않았습니다."
- 종합 캐릭터 타이틀(가장 크게) → 자세 카드들 → 체형 비율 카드 → 스타일 추천 + 상품 슬롯 → 스켈레톤 도식(정면/측면) → 면책 문구("의료 진단이 아닌 재미/참고용")
- 버튼: **공유하기**(`navigator.share` with `files` 지원 시만 표시; 미지원 시 "이 브라우저는 공유를 지원하지 않습니다"), **다시 측정**
- AdSense 배너: 자세 카드와 비율 카드 사이 1개, 공유 버튼 아래 1개
- 새로고침/뒤로가기 시 결과 소멸

## 5. 분석 지표

모든 좌표는 정규화 좌표(0~1)이며 영상의 종횡비로 보정하여 각도를 계산한다. 절대 치수(cm)는 산출하지 않는다.

### 5.1 정면 자세 (`analysis/front.ts`)
| 항목 | 계산 | 등급 경계 |
|---|---|---|
| 어깨 높이 차 | 어깨선(L↔R) 기울기 각도 | 양호 <2° / 주의 2~4° / 불균형 ≥4°, 높은 쪽 표기 |
| 골반 높이 차 | 고관절선 기울기 각도 | 동일 |
| 머리 기울기 | 귀 연결선 기울기 각도 | 동일 |
| 몸 중심선 편위 | 코·어깨중점·고관절중점·발목중점 x 값의 최대 편차 / 어깨 너비 ×100 | 양호 <5% / 주의 5~10% / 불균형 ≥10% |
| 무릎 정렬 | 무릎 간격 / 발목 간격 | X자 경향 <0.8 / 중립 0.8~1.3 / O자 경향 >1.3 |

### 5.2 측면 자세 (`analysis/side.ts`)
| 항목 | 계산 | 등급 경계 |
|---|---|---|
| 거북목(전방 머리) | 귀–어깨 벡터와 수직선 사이 각도 | 양호 <5° / 주의 5~15° / 거북목 경향 ≥15° |
| 라운드숄더 | 어깨 x가 귀–고관절 선보다 앞으로 나간 거리 / 몸통 길이 ×100 | 양호 <5% / 주의 5~12% / 라운드숄더 경향 ≥12% |
| 골반 경사 | 어깨–고관절–무릎 각도(180° 기준 편차) | 중립 <5° / 전방·후방경사 경향 ≥5° (부호로 구분) |
| 상체 기울기 | 고관절→어깨 벡터 vs 수직 | 양호 <3° / 주의 3~7° / 기울어짐 ≥7° (앞/뒤) |

### 5.3 체형 비율 (`analysis/proportion.ts`, 정면 데이터)
| 항목 | 계산 | 분류 |
|---|---|---|
| 어깨:골반 | 어깨 너비 / 고관절 너비 | 역삼각형 >1.15 / 균형형 0.9~1.15 / 삼각형 <0.9 |
| 상체:하체 | (어깨중점~고관절중점) / (고관절중점~발목중점) | 상체형 >0.62 / 균형 0.52~0.62 / 하체(롱다리)형 <0.52 |
| 허벅지:종아리 | (고관절~무릎) / (무릎~발목) 평균 | 참고 수치만 표시, 등급 없음 |

허리는 포즈 랜드마크에 없으므로 측정하지 않는다.

### 5.4 등급 → 비유 캐릭터 (`analysis/grade.ts`, `copy.ts`)
- 각 항목은 `good | warn | bad` 3단계(비율 항목은 분류 라벨).
- **종합 타이틀**: `bad` 항목 중 수치가 경계값 대비 가장 멀리 벗어난 항목(초과 비율 = (수치 − bad 경계) / bad 경계)의 캐릭터를 선택. `bad` 없고 `warn`만 있으면 같은 방식으로 warn 캐릭터, 전부 good이면 "운동선수처럼 완벽합니다 🏅".
- 캐릭터 매핑: 거북목→"당신은 거북이시군요 🐢", 라운드숄더→"고양이처럼 등이 둥글어요 🐱", 어깨/골반/머리 좌우 차→"피사의 사탑 🗼", 중심선 편위→"바람 맞은 갈대 🌾", 상체 기울기→"앞으로 쏠린 스키점프 선수 ⛷️", 골반 경사→"오리 엉덩이 🦆(전방)/주저앉은 곰 🐻(후방)", O자→"카우보이 다리 🤠", X자→"펭귄 다리 🐧". 비율은 중립 톤: "수영선수 체형 🏊", "안정감 있는 기둥형 🏛️", "플라밍고 롱다리 🦩".
- **항목별 메시지**도 3단계 톤 문구를 `copy.ts`에 모아둔다(항목 × 3단계). 각 문구에 수치 템플릿(`{deg}`, `{pct}`, `{ratio}`)과 교정/스트레칭 팁 1개를 포함.

### 5.5 스타일 추천 (`analysis/style.ts`)
- 입력: 어깨:골반 분류 × 상체:하체 분류 (3×3 = 9 조합).
- 출력: 상의 / 하의 / 아우터 / 피하면 좋은 것 — 각 1~2줄. 문구는 `copy.ts`.
- 각 추천 항목(상의·하의·아우터) 옆에 **상품 슬롯** 1개(총 최대 3개). 상품은 `public/products.json`에서 `bodyType`(9조합 키 또는 `any`) × `category`(top/bottom/outer)로 필터링해 랜덤 1개 노출. 항목: `image`, `name`, `price`, `url`, `bodyType`, `category`. 해당 조합 상품이 없으면 네이티브 광고 유닛으로 폴백.

## 6. 코드 구조

```
bodyscan/
├─ index.html
├─ vite.config.ts, tsconfig.json, package.json
├─ public/
│  ├─ models/pose_landmarker_lite.task      모델(같은 출처 서빙)
│  ├─ wasm/                                  @mediapipe/tasks-vision WASM 번들
│  ├─ products.json                          제휴 상품 목록
│  ├─ manifest.webmanifest
│  └─ sw.js                                  오프라인 캐시
└─ src/
   ├─ main.ts            상태 머신, 화면 전환
   ├─ camera.ts          getUserMedia 열기/닫기, 트랙 stop 보장
   ├─ pose/
   │  ├─ detector.ts     PoseLandmarker 초기화(VIDEO 모드), detectForVideo 래핑
   │  ├─ landmarks.ts    랜드마크 인덱스 상수, 타입
   │  ├─ gating.ts       fullBody / facingFront / facingSide 판정 (순수)
   │  └─ sampler.ts      시간 창 수집 → 좌표별 중앙값 (순수)
   ├─ analysis/
   │  ├─ geometry.ts     각도·거리·기울기 (순수)
   │  ├─ front.ts        5.1
   │  ├─ side.ts         5.2
   │  ├─ proportion.ts   5.3
   │  ├─ grade.ts        등급·종합 캐릭터 선택 (5.4)
   │  └─ style.ts        스타일 추천 (5.5)
   ├─ copy.ts            모든 사용자 문구(비유, 팁, 스타일 문구)
   ├─ ads/
   │  ├─ banner.ts       AdSense 슬롯 마운트/언마운트 (start/result에서만)
   │  └─ products.ts     products.json 로드(시작 화면에서 미리), 필터·폴백
   ├─ ui/
   │  ├─ screens.ts      각 화면 DOM 템플릿
   │  ├─ overlay.ts      스켈레톤·가이드 실루엣 캔버스
   │  ├─ privacy.ts      네트워크 요청 카운터 인디케이터
   │  ├─ result.ts       결과 화면 렌더
   │  ├─ shareCard.ts    결과 카드 PNG 생성 + navigator.share
   │  └─ qr.ts           데스크톱용 QR
   └─ speech.ts          Web Speech 음성 안내(옵션, 기본 켜짐·토글 가능)
```

의존성: `@mediapipe/tasks-vision`, 개발용 `vite`, `typescript`, `vitest`. QR은 소형 라이브러리(`qrcode`) 허용.

### 데이터 흐름
```
camera(video) → detector.detectForVideo → landmarks[33]
   → gating(상태별 판정) → sampler(3초 수집) → median landmarks
   → front/side/proportion → grade → copy → result 렌더 / shareCard
   → overlay(매 프레임 스켈레톤)
```

## 7. 에러 처리
| 상황 | 처리 |
|---|---|
| 카메라 권한 거부 | 설정 경로 안내 화면 + 재시도 |
| 모델/WASM 로딩 실패 | 재시도 버튼, 오프라인이면 "최초 1회는 인터넷 연결 필요" |
| 전신 30초 미인식 | 힌트 표시, 계속 대기 |

## 8. 테스트
- Vitest 단위 테스트(카메라 불필요, 순수 함수): `geometry`, `gating`(합성 랜드마크로 정면/측면/전신 판정), `sampler`(중앙값·이상치), `front/side/proportion`(알려진 좌표 → 기대 각도), `grade`(경계값, 종합 캐릭터 선택), `style`(9조합 모두 문구 존재), `products`(필터·폴백).
- `copy.ts` 완전성 테스트: 모든 항목 × 3단계 문구, 9조합 스타일 문구 존재.
- 수동 테스트: 실제 폰(iOS Safari, Android Chrome)에서 전 플로우, 비행기 모드 동작, 인디케이터 0건 유지, 공유 시트.
